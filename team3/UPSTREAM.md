오브제 브랜치는 프로젝트가 저장소 루트에 놓여 있다. 통합 작업 공간에서는
다른 팀과 구분하기 위해 `team3/object/` 아래로 배치했으며 파일 내용은 수정하지 않았다.
두 Team3 브랜치 전체를 병합한 상태는 아니며, 필요한 프로젝트 파일을 가져온 구성이다.

Team2 브랜치의 마지막 커밋은 `team1/output/emotion_peaks.txt`를 복구한 것이다.
`team2/` 소스에는 현재 로컬과 차이가 없다. 이번 코드 동기화는 최신 `origin/team1`의
Team1 구성을 유지하므로 다른 브랜치의 Team1 출력 샘플을 추가하지 않았다.

## 코드 동기화와 실행 연동의 범위

- 배경 앱은 Flask 서버와 브라우저 렌더러로 구성된다. 입력 이미지와 JSON은
  `background/input/storyboard/`, 내보낸 결과는 `background/output/<run>/`에 놓인다.
- 오브제 생성 스크립트는 실행한 작업 폴더 기준으로 `dream_scenes.json`을 읽고
  `output_objects/scene_<번호>/`에 저장한다. 이 스크립트를 실행할 때는
  `team3/object/`를 작업 폴더로 사용해야 한다.
- 오브제 생성에는 ComfyUI, 모델 파일 및 관련 Python 패키지가 필요하다.
  `train_lora.py`에는 원 작성자 환경의 절대경로와 설치·학습 명령이 포함되어 있다.
  이번 동기화에서는 이 파일을 수정하거나 실행하지 않았다.
- 저장된 `dataset/`은 학습 자료다. 이를 장면별 최종 오브제 출력으로 간주하면 안 된다.
- Team4는 기존 초기 파이프라인 상태를 유지한다. 원본 배경과 가공 배경의 구분,
  오브제 출력 경로 연결, 전체 시스템 실행 검증은 별도 연동 작업이다.

이번 작업은 팀별 소스 코드를 함께 볼 수 있도록 최신 스냅샷을 배치한 것이다.
전체 앱 실행, 이미지 생성, LoRA 학습, MP4 렌더링을 검증했다는 뜻은 아니다.
