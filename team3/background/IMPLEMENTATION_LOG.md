## 3. 아피찻퐁 프로젝트 (Apichatpong Project) — ★ 캡스톤2 현행 과제

### 3-1. 이번 미션의 목적
2팀의 더미 이미지·사운드를 재료로, **바람 · 빛 · 안개 · 여백이 강조된 추상적 꿈 애니메이션을 캔버스 위에서 실시간으로 그려내는** 인터랙티브 캔버스 아트.

- **원본 사진은 화면에 한 번도 나오지 않는다.** 사진은 보이지 않는 오프스크린 캔버스에만 깔리고, 입자들이 그 위를 돌아다니며 **픽셀 색을 스포이드처럼 빨아들여** 점과 선을 남긴다. 관객이 보는 것은 사진이 아니라 입자 밀도가 우연히 만든 잔상이다.
- **정적 변환·저장이 아니다.** 매 프레임 다시 계산된다.
- **팀 파이프라인:** `2팀(기억 재구성) → [3팀] 꿈 이미지 생성 → 4팀(꿈 재현 애니메이션)`. 단 **현 단계는 규격 합의 전이며 각 팀이 더미로 각자 목표를 달성하는 것이 우선**이다.
- **레퍼런스:** 아피찻퐁 위라세타쿤(《엉클 분미》, 《열대병》, 《메모리아》), kickthemachine.

### 3-2. ★ 방향 전환 — 왜 윤곽선(Canny)을 버렸는가
초기 캡스톤2 구현은 캡스톤1의 `get_shape`(Canny 외곽선 추출)를 그대로 이어받아, 뽑아낸 좌표를 입자가 **따라 그리는** 방식이었다. 이것을 2026-09-12 전면 폐기했다.

- 윤곽선을 따라 그리는 것은 **형태를 그대로 베끼는 것**이다. 교수님이 요구한 '아피찻퐁 스타일의 몽환적 추상'과 'Open-ended AI 기법'에 부합하지 않는다.
- 그 위에 필터를 덮는 방식도 마찬가지다. 결국 **원본이 형태 그대로 노출되고 효과만 얹히는** 구조였다.
- → **픽셀 샘플링 기반 파티클 추상 렌더링으로 전환.** 형태는 '그려지는' 것이 아니라 입자가 어디에 얼마나 머무는가로 **창발**한다. 어두운 픽셀 위의 입자는 거의 보이지 않고 밝은 픽셀 위의 입자만 남으므로, 형태가 **빛으로만** 드러난다.
- 부수 효과로 백엔드에서 **OpenCV·numpy 의존이 완전히 사라졌다**(`pip install flask flask-cors` 만 필요).

### 3-4. 현행 구조 요약 (`index.html`) — 자세한 근거는 Work Log
- **렌더:** 원본은 보이지 않는 샘플러에만 깔린다. 파편 14000개가 자리의 색을 머금어 `'lighter'` 로 점을 찍는다(색 8단계 양자화 + 계수 정렬로 버킷당 한 번 그림).
  - 노출 보정 `liftShadows` — 이미지 중앙값이 `LIFT_MID 0.36` 에 닿도록 감마(하한 0.40). 빛 위치·3축·형태 지도는 보정 전 원본(`rawCur`)으로.
  - 노출 제한 `glowNow` — 원본 평균 밝기 × 막 빛 배율이 `GLOW_CAP 0.50` 을 넘으면 빛 배율을 낮춘다(타오르다만 해당).
- **기승전결 물리 (`ACTS`)** — settle·chaos·swirl·rise·wind·fric·glow·fog·spread·jit + 09-13 추가 **hold**(전 0.020, 어두운 파편만 제 자리로) · **home**(기·결 0.50, 제 자리에서 되살아남) · **sparse**(승 0.60, 평평한 곳 파편 비우기 = 화면 안 여백).
- **입력이 움직이는 것:** 이미지 명암 → 안개·바람·빛 목표(`sceneMood` 가 `fogRaw`/`glowRaw`/`windRaw` 로 읽음), 입력 사운드 세기 → 흩날림·맺힘·빛(`sndLevel`), DB → 색 보정·해체·GA 적합도. **난수로 흐름을 정하지 않는다.**
- **감정 가중치 (`EMOTIONS`, 09-25 신규)** — 2팀 `main_emotion`(1팀 7종, 09-27) 또는 `emotion`+`intensity` → 표에서 8축 배율(`mut·sat·warm·fog·glow·wind·wet·rate`)을 뽑아 `driftEmo()` 가 막과 같은 속도로 스며들게 한다. **전부 0.75~1.25 의 곱하기**이고, 라벨이 비거나 표에 없으면 중립(1.0)이라 **09-13 화면이 그대로 남는다.** 적용 지점 4곳: 해체는 `mutFx`(소비 쪽만, `mutRate` 자체는 불변 — GA 탐색 폭 보호), 3축은 `Target = Raw × EMO`, 색은 `dbTarget()`(폐루프 **목표**만 이동), 사운드는 `wet`·`rate` 만.
- **DB 색 보정 (`colorLoop`)** — 0.5초마다 화면을 재서 장면별 기억값을 막별 DB 목표로 적분. 채도 → 안개 색 강도, 색 온도 → 밝기 0.7 미만 파편. 휘도 보존(`gradeRGB`).
  - ★ **감정은 출력이 아니라 과녁에 건다(`dbTarget`).** 적분 제어라 출력(`mistChroma`)에 배율을 곱하면 다음 측정에서 오차로 읽혀 되감기고, 감정은 지워진 채 보정값만 상한에 붙어 제어가 죽는다. 목표를 밀면 루프는 그대로 돌고 수렴 지점만 옮겨간다. 이동 폭은 그 막 **허용편차의 절반** 안으로 묶었다.
- **유전 알고리즘** — 개체 24, 160프레임마다. 적합도 = (DB 근접도) × (막 적합도). 돌연변이율 = DB 에서 멀수록 크게(형체 해체 세기). 여백으로 빈 화면은 재지 않는다.
- **사운드** — 재생기 2개 핑퐁(소스 노드 영구 2개). 체인: 저역컷→저역강조→고역광택→dry/리버브 3.4초/6초→고역차단×2→압축→보정(make)→호흡(0.11Hz)→출력, `preservesPitch=false` 로 피치 이동. [원음/변환] 비교. 변환 전후 음량 0dB(결 −3dB).
- **흐름** — 장면 10초(`SCENE_PERIOD 600`), 해체는 장면 길이와 분리(`DISSOLVE_FRAMES 900`). 자동 전환 시 여백(1.5초 비움 + 0.75초 정적, 결→기 2.5초 + 3초). 리본 칸 클릭·←→·1~6·스페이스(머물기).
- **패널** — 서사 / 입력이 움직이는 것 / 사운드 변환 / 아피찻퐁 DB·유전 알고리즘. 모든 행 한 줄 고정.
- **공기 중의 물기 (`MOI`, 09-27 · Work Log 35)** — 글이 부른 비·눈·서리·김을 본 파편과 별도 층(1600)으로. 김은 이미지의 '틈'에서 솟는다.
- **꿈의 물리 법칙 (`LAW`, 09-27 · Work Log 34)** — 2팀 `physics_laws` 중 배경 현상 6종(바람 없는 흔들림·원인 없는 빛·형체의 숨·가늘어져 사라짐·고정된 거리·어긋난 박자)을 막 위에 얹는다. 없으면 0.
- **09-27 추가** — 입력 두 갈래(`input/storyboard/` · `input/dummy/`) · 원본 바탕 `BASE_ALPHA 0.01`(필터처럼 보이지 않는 선) · 번짐 크기 `GLOW_SIZE 0.7`(잠정) · **참조 작가 섞기 `ref()`**(장면 글이 부른 작가를 아피찻퐁 위에 ≤50%) · 장면별 자동 내보내기 · `[` `]` `\` 키와 패널 인과 사슬 제거.

### 3-7. ★ 작업 원칙 (되풀이하지 말 것)
> 09-13 Work Log 깊숙이 묻혀 있던 것을 끌어올렸다. 매 세션 적용된다.

- **화면 톤은 시뮬레이션으로 판단하지 않는다.** 저해상 버퍼 시뮬이 먼지 밝기를 30배 과대평가해, 밝음 → 어두움으로 두 번 헛발질했다. **사용자 육안 확인이 유일한 기준**이며, 한 번에 한 축만 바꾼다.
- **조용한 실패를 만들지 않는다.** `catch {}` 로 삼킨 탓에 사운드 변환이 왜 안 걸리는지 오래 못 찾았다. 진단 표시(패널 `체인`, 서버 415 응답 등)는 유지할 것.
- **폐루프에는 출력이 아니라 목표를 건다.** 적분 제어에 배율을 곱하면 다음 측정에서 오차로 읽혀 되감기고, 보정값만 상한에 붙어 제어가 죽는다(09-25 감정 채도).
- **측정은 같은 세션 안에서 A/B 로.** 절대값은 배경 부하에 휘둘린다 — 09-25 에 사용자 크롬이 떠 있어 프레임 중앙값이 25.8→54.1ms 로 보였고, 같은 세션 A/B 로 재보니 실제 변화는 정렬 6.3ms vs 20.8ms 였다.
- **창발을 얹을 때 원래 성격의 '중심'을 옮기지 않는다.** 변동을 주려던 것이 평균까지 바꿔버리기 쉽다(09-25 호흡 9.1초 → 3.9초). 얹은 뒤 반드시 **사람이 읽는 단위**(초·센트·dB)로 환산해 확정값과 비교한다.
- **보고하는 지표가 관객이 보는 것과 같은지 먼저 확인한다.** 내부 상태(예: 파편의 집 분포)가 바뀌어도 화면에 안 나타날 수 있다(09-25: `settle=0` 인 막). 최종 화면을 합성해서 잰다.
- **평균값을 눈대중하지 않는다.** 고정 비네트의 평균 어둠을 0.34 로 짐작했으나 실제는 0.256 이었고, 그 차이가 화면 밝기 -16% 로 나타났다. 잴 수 있으면 잰다.
- **기록에 쓰지 않은 값을 지어내지 않는다.** 감정 라벨이 없으면 중립으로 두고 패널에 '(미정의)'로 표시한다. 없는 값을 채우면 화면이 거짓말을 한다.

### ★ 설계 판단 — 폐루프에 감정을 거는 자리
요구사항의 예시는 `drawVeil()` 의 `mistChroma` 에 감정 배율을 곧바로 곱하는 것이었다. **그대로 하면 감정이 지워지고 폐루프가 죽는다.**
- 이 루프는 적분 제어다. 화면을 재서 DB 목표와의 오차만큼 보정값(`c.mist`)을 누적한다.
- 출력에 배율을 곱하면 다음 측정에서 화면 채도가 그만큼 달라져 보이고, 루프가 그것을 **오차로 읽어 반대로 되감는다.** 몇 초 뒤 감정은 흔적도 없이 사라지고 `c.mist` 만 상한(2.5)이나 하한(0.3)에 붙어 제어가 죽는다.
- → **출력이 아니라 과녁을 민다.** `dbTarget()` 이 `T.sat × EMO.sat`, `T.warm + EMO.warm` 을 돌려주고, 루프는 손대지 않은 채 그대로 돌되 수렴 지점만 감정 쪽으로 옮겨간다. 이동 폭은 **그 막의 허용편차 절반** 안으로 묶어, 감정이 아무리 세도 화면이 아피찻퐁 군집 밖으로 끌려나가지 않는다.
