## 2. 0917 미팅 정리 (원문)

### 전체 목표
인간의 감정과 기억을 수집한 뒤, Open-Ended AI와 생성 모델을 이용해 인간과 로봇이 함께 꾸는 꿈을 이미지와 영상으로 구현한다.
전체 과정: 1) 공감대 및 감정 분석 2) SF 형태의 꿈 스토리보드 생성 3) 꿈 이미지 생성 4) 꿈 애니메이션 제작.
스토리는 기승전결에 해당하는 4개의 장면으로 구성한다.

### 1. 기억 및 감정 추출 (신진성, 이동규)
- EEG 또는 카메라 영상을 이용해 공감 장면과 8가지 감정을 추출한다.
- 표정 인식이나 뇌파 데이터를 머신러닝으로 분류한다.
- 감정, 표정, 사운드, 나레이션이 발생한 시점을 정렬하여 데이터셋을 만든다.
- 우선 한 명을 대상으로 구현한 뒤 여러 명을 동시에 분석하는 방향으로 확장한다.
- 실제 참여자를 확보하기 어려우면 시뮬레이션 데이터를 활용할 수 있다.
- 카메라 한 대로 멀리 있는 여러 사람의 표정을 인식할 수 있는지 확인해야 한다.
- 거리 증가에 따른 인식률 저하와 사람별 영역 검출 방법을 검토한다.
- 공감 반응이 크게 나타난 장면을 강하게 각인된 꿈의 기억으로 사용한다.

### 2. 기억 재구성과 꿈 스토리보드 생성 (강민재, 안근형)
- 추출된 감정, 사운드, 나레이션을 조합해 하나의 꿈 이야기를 만든다.
- 단순히 GPT로 소설을 생성하는 방식은 피하고 Open-Ended AI를 활용한다.
- 완전히 Open-Ended 방식만 사용하면 이해하기 어려울 수 있으므로 Close-Ended AI와 결합한다.
- 꿈 장면을 배경과 엔티티·오브제로 분리하여 구성한다.
- 배경 이미지와 장면 설명을 바탕으로 여러 이미지를 조합하는 Context Engineering 방법을 검토한다.
- 일반적인 소설 형식이 아닌 꿈에 적합한 새로운 스토리 표현 방식을 고민한다.
- 기존 생성 방식과의 차별점을 만들고 장면 사이를 Open-Ended AI로 연결하는 방법을 제안한다.
- 사운드 역시 기존 음원을 그대로 연결하지 않고 작은 단위로 나눈 뒤 Open-Ended 방식으로 변형·진화시킨다.
- 최종 결과물은 기승전결 구조의 4개 장면으로 구성된 꿈 스토리보드이다.

### 3. 꿈 이미지 및 사운드 생성 (김정민, 신준우) ← **우리**
1. 스토리보드를 바탕으로 아피찻퐁 위라세타쿤 스타일의 꿈 장면을 생성한다.
2. 아피찻퐁 관련 이미지 자료를 데이터베이스화하고, 사용 가능한 데이터의 양을 먼저 확인한다.
3. 데이터베이스를 기반으로 꿈의 배경 이미지를 생성하는 모델을 검토한다.
4. 파티클 기반 추상 렌더링, 물리엔진, Open-Ended AI 엔진을 결합하는 방법을 고려한다.
5. 인간의 꿈은 배경, 로봇의 꿈은 추상적·기하학적 오브제로 표현한다.
6. 배경과 오브제가 자연스럽게 결합되어 하나의 꿈 장면이 되어야 한다.
7. 스토리와 생성 이미지 사이의 연관성이 명확해야 한다.
8. 장면이 단순히 전환되는 것이 아니라 이미지가 점진적으로 변형되는 과정이 필요하다.
9. 사운드도 장면 변화와 함께 창발적으로 변하도록 구성한다.

### 4. 꿈 애니메이션 제작 (임지섭, 박태건)
- 생성된 꿈 이미지를 이용해 애니메이션을 제작한다.
- Open-Ended 방식과 Close-Ended 방식을 함께 사용한다.
- 장면과 장면 사이의 연결이 매끄럽게 이어져야 한다.
- 현재 배경 중심의 결과에서 벗어나 꿈속 대상과 오브제가 실제로 등장하도록 한다.
- Unity는 그리드와 셀 기반 표현 및 영상 변환에 활용할 수 있다.
- 해상도에 따라 셀 규칙을 변화시켜 몽환적인 효과를 만든다.
- 점 형태의 거친 결과보다는 깨끗한 원본 이미지가 점진적으로 변형되는 방식을 우선 검토한다.
- 이미지 생성팀의 결과물을 Unity 또는 영상 생성 시스템에서 바로 받을 수 있도록 인터페이스와 데이터 형식을 미리 정해야 한다.

### 공통으로 준비할 내용
- A. 각 팀의 입력과 출력 형식을 정의한다.
- B. 감정·사운드·나레이션·스토리보드·이미지·영상 사이의 연결 구조를 정한다.
- C. 팀 간 전달 파일 형식, 해상도, 장면 수, 메타데이터 규칙을 통일한다.
- D. Open-Ended AI가 실제로 사용되는 부분과 일반 생성 모델이 사용되는 부분을 구분한다.
- E. 기존 방식과 비교했을 때 무엇이 새롭고 창발적인지 설명할 수 있어야 한다.
- F. 최종적으로 인간의 꿈 배경과 로봇의 꿈 오브제가 결합된 4장면의 꿈 영상을 제작한다.

## 4. 작업할 때마다 감안할 점

1. **범위** — 시스템 I(배경)만. 오브제·장면 전환 총괄·영상 출력까지 끌어오지 않는다. 오브제가 얹힐 여지를 남긴다.
2. **입력** — 2팀 스토리보드 json(1·2팀 협력 산출물). 규격은 넘기는 쪽에 맞춘다. 감정 라벨 문의는 **2팀**에. `vector` 는 쓰지 않는다(09-27 확정). 사운드 담당은 3·4팀 합의 사항(2팀이 정할 일 아님).
3. **4장면 기승전결** 이 합의 단위다.
4. **단순 필터링 금지 ↔ 깨끗한 원본의 점진적 변형** — 두 요구가 부딪힌다. 원본이 '사진 + 필터'로 보이지 않게 하되 형체는 읽혀야 한다(09-27 원본 바탕 0.01 결정).

6. **Open-Ended 와 생성 모델을 구분해 말할 수 있어야 한다** — 생성 모델(사진)은 '무엇이 있는 장면인가', 우리 엔진(DB·파티클·GA)은 '어떻게 꿈이 되는가'.
